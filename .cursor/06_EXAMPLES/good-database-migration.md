# Good Database Migration Reference Implementation
## AI NEET Exam App

---

# Purpose

This document defines the canonical database migration pattern for the AI NEET Exam App.

It provides guidance for creating safe, repeatable, reversible, and production-ready Alembic migrations.

The repository implementation is the source of truth.

Database migrations are permanent historical records and should never be rewritten after production deployment.

---

# Design Principles

Every migration should be

✓ Atomic

✓ Reversible

✓ Idempotent where practical

✓ Production safe

✓ Small

✓ Easy to review

✓ Well documented

✓ Backward compatible whenever possible

changes

temp

test

Migration names should describe the business purpose.

---

# Foreign Keys

Always

Use explicit names

Review cascading rules

Verify delete behaviour

Document relationships

Avoid accidental cascade deletes.

---

# Indexes

Create indexes for

Foreign Keys

Frequently filtered columns

Search columns

Sorting columns

Unique constraints

Avoid unnecessary indexes.

Indexes increase write cost.

---

# Constraints

Use

NOT NULL

CHECK

UNIQUE

FOREIGN KEY

Only when supported by business rules.

Do not rely solely on application validation.

---

# Enum Changes

Prefer additive changes.

Avoid removing enum values immediately.

Plan deprecation.

Maintain backward compatibility where practical.

---

# Data Migrations

Separate

Schema migration

↓

Data migration

↓

Constraint tightening

Avoid large data updates inside a single transaction when dealing with production-scale datasets.

---

# Rollback Strategy

Every migration should include

Upgrade

Downgrade

Downgrade should restore previous schema whenever feasible.

If rollback is impossible

Document the reason clearly.

---

# Transaction Safety

Use transactions.

Avoid partial schema updates.

Never leave database in inconsistent state.

---

# Backward Compatibility

Support rolling deployments.

New application version should remain compatible during deployment whenever practical.

Avoid breaking running application instances.

# Common Anti-Patterns

Never

❌ Rewrite production migrations

❌ Combine unrelated schema changes

❌ Skip downgrade

❌ Drop columns without migration plan

❌ Drop tables without backup

❌ Remove indexes blindly

❌ Assume empty database

❌ Ignore existing production data

❌ Lock large tables unnecessarily

❌ Depend entirely on autogenerated SQL

# Cursor Instructions

When creating a migration

1. Inspect repository.
2. Review existing schema.
3. Review SQLAlchemy models.
4. Generate migration.
5. Review generated SQL.
6. Add indexes and constraints intentionally.
7. Implement downgrade.
8. Test upgrade.
9. Test downgrade.
10. Update documentation if required.

Never generate destructive migrations without explicit approval.

Never remove production data without a documented migration strategy.

---

# Final Principle

A migration is a permanent part of the project's history.

It should be safe, reversible, well-reviewed, and understandable years after it was written.

Every migration in the AI NEET Exam App should preserve data integrity, support production deployment, and reflect the same engineering quality as application code.
