# Cursor Instructions

Before generating release notes

1. Inspect repository.

2. Review merged Pull Requests.

3. Review Feature Specifications.

4. Review ADRs.

5. Review changelog.

6. Review deployment documentation.

7. Review release audit.

8. Confirm production readiness.

9. Do not invent completed work.

10. Reference repository evidence.

---

# Final Principle

Release Notes communicate the value, impact, and operational readiness of a release.

They should be accurate, evidence-based, easy to understand, and fully traceable to repository artifacts such as Feature Specifications, ADRs, Pull Requests, Issues, and Deployment documentation.

Never include unverified features or undocumented changes.
