Cursor Instructions
------------------------------------------------------------

Before updating the changelog

1. Inspect merged Pull Requests.

2. Review Feature Specifications.

3. Review ADRs.

4. Review Release Notes.

5. Review Deployment documentation.

6. Verify completed work.

7. Never document unreleased functionality.

8. Never invent completed features.

9. Maintain chronological order.

10. Preserve previous release history.

------------------------------------------------------------
Final Principle
------------------------------------------------------------

The CHANGELOG is the permanent history of the project.

Every entry must correspond to completed, verified work.

Every significant change should reference Feature Specifications, ADRs, Pull Requests, Issues, and Release Notes.

Never rewrite history.

Never remove previous releases.

Always maintain an accurate, chronological, evidence-based record of the evolution of the AI NEET Exam App.
